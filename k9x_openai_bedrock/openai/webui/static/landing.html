What K9-AIF adds

One governance configuration that holds for every agent on every runtime. The adapter wraps the SDK; it doesn't change it.

K9-AIF Shield on every step

The request, each tool call, each tool result, every agent's reply and the final answer pass k9x Shield.

K9-AIF Zero Trust

Who may run the request, and who may reach each agent, from a role policy the solution owns.

K9-AIF K9 Model Router

Picks the model for every call, eligibility first: a tool-using agent only gets a model that can call tools.

K9-AIF Agents in YAML

The OpenAI agent is declared in K9-AIF agent YAML. A tool it isn't registered for fails at start-up.

K9-AIF Sole broker

The adapter builds every agent and tool itself, so nothing ungoverned can be slipped in.

K9-AIF One layer, every runtime

The K9-AIF framework

An architecture-first framework for governed, observable multi-agent systems. Abstract building blocks (ABBs) define the contracts; solutions extend them. Router, Orchestrator, Squad and Agent, with governance applied by construction.

  • The adapter is an orchestrator: the Router sends it the event weather.lookup.
  • On this path the SDK's Runner and agent take the place of Squad and Agent.
  • Failures and human-review signals propagate with their own type.
  • SDK traces stay local unless you choose to export them.

How it works

One request, from the page to the answer.

  1. Zero Trust checks the caller's role for the action weather.lookup.
  2. Shield ingress screens the request before the OpenAI Agents SDK starts.
  3. Agent turn: Zero Trust again, for the action openai_agent:WeatherAgent.
  4. K9 Model Router picks the model for each call; the SDK calls it through its OpenAI-compatible API.
  5. Each tool call is screened before it runs, and each tool result before the model reads it. The weather tool looks coordinates up from the zip record itself, never from the model.
  6. Every reply and the final answer pass Shield egress, and the page shows the trace.
