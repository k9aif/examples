K9Chat · an application built on K9-AIF

A chat assistant built to show
how a governed AI application works.

K9Chat is a working demo of a solution built on the open-source K9-AIF framework, not a chat service. Every message passes k9x Shield on the way in and out; anything a visitor stores is screened by Shield and Granite Guardian before it is saved; the model has no tools. It runs on self-hosted models ({{ model }} on one GPU), not a third-party AI API.

The code is open source. Download it, change it, and run it on your own on-premise models.

How it stays safe

Each card is a mechanism running in this deployment, with a link to the code that implements it.

Governed by construction

k9x Shield runs around every agent call, built in by the framework rather than added by the app: prompt-injection, input-size and personal-data checks on the way in, a personal-data check on the way out.

A second, semantic gate

Granite Guardian, a purpose-built safety model, reads what pattern checks can miss, such as a reworded attack. Chat messages {{ 'ON' if guardian_chat else 'OFF' }} HERE

guard_agent.py →

Nothing is stored unscreened

Project files, project instructions and learned facts pass Shield and Guardian before they are saved, whatever the chat setting. If the safety check can't run, nothing is saved.

persist_screen.py →

Reads the web safely

Pasted links are fetched only from public addresses, re-checked on every redirect and on the address actually connected to, so a link can't reach the private network. Each page is screened for planted instructions before the model reads it.

url_fetch.py →

No tools, no blast radius

The model can only write text. It can't run code, open files, call APIs or reach the network, so the worst a hostile prompt can do is produce a bad answer.

chat_agent.py →

Fair use of one GPU

Per-visitor and per-IP message limits, a cap on generations running at once, and a temperature gate that stops new work while the GPU is hot.

Architecture

K9Chat is an SBB, a solution building block: the framework provides the building blocks (ABBs) and K9Chat adds only what is specific to a chat application.

ChatAgent

Extends the framework's BaseAgent, so Shield wraps every call automatically. Builds the prompt from the conversation and the context blocks, each labelled with where it came from.

Model router

Calls go through the framework's llm_invoke and model router: each task (chat, reasoning, guardrails) resolves to a model alias in config, so models change without code changes.

Knowledge base

K9-AIF and K9X documentation in a vector store (ChromaDB), retrieved per message in Framework Mode. A cross-encoder reranker on CPU decides when a curated FAQ answer is good enough to return directly.

Projects

Each visitor's own files and instructions, one vector collection per project so nothing leaks between projects, screened before storage.

Two modes

Framework Mode: scoped to K9-AIF, grounded in its documentation, offline. Internet mode: a general assistant with live web search and link reading.

Self-hosted models

Ollama on a local GPU, or any OpenAI-compatible server. No third-party AI API: prompts and documents go only to the deployment's own models. (In Internet mode, your question is also sent as a search query through a self-hosted search proxy.)

Scope

  • A demo, not a chat service. For everyday chat, use Claude, ChatGPT or Grok. K9Chat is here to show what an application built on K9-AIF looks like and how it behaves.
  • Limits: {{ limit_short }} messages per {{ limit_short_window }} and {{ limit_daily }} per day for each visitor, with a looser limit per network address. One GPU is shared by everyone.
  • No tools. It doesn't run code, browse on its own, or act on your behalf; it reads a link only when you paste one.
  • Your projects are yours. Files and instructions you add are visible only to you, and each project is kept in its own collection.

Run it yourself

K9Chat is open source (Apache-2.0) in github.com/k9aif/examples. Point it at your own models: Ollama on your hardware, or any OpenAI-compatible server.

git clone https://github.com/k9aif/examples.git k9-aif-examples
cd k9-aif-examples
k9chat/setup.sh          # Python venv + pip install (requirements.txt, k9-aif from PyPI)
# edit k9chat/.env: OLLAMA_BASE_URL and the model names you have pulled
k9chat/setup.sh seed     # one time: load the knowledge base
k9chat/setup.sh run      # http://localhost:7777

By hand instead: python3.11 -m venv k9chat/.venv, then pip install -r k9chat/requirements.txt and pip install --no-deps k9-aif==1.18.7. Prefer a container? k9chat/ubuntu/build-run.sh all builds and starts one with Podman.
