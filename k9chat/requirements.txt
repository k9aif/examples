# k9chat's own scoped dependency list -- NOT the framework's full
# requirements.txt. k9chat imports k9_aif_abb/ directly as source (see
# ubuntu/README.md), but only a narrow slice of the framework is actually
# reachable from k9chat's code: config loading, llm_invoke's routing
# (which pulls in SQLAlchemy-backed routing-state storage), Ollama-backed
# LLM/embedding calls, ChromaDB retrieval, and the FAQ reranker.
#
# Every package below, direct AND transitive, is pinned. First cut
# (2026-09-21) pinned only the ~16 packages k9chat's code touches directly
# and let pip resolve the rest -- broke production: pip picked
# starlette==1.6.0 (a major-version jump with breaking changes) instead of
# the framework's proven starlette==0.52.1, and FastAPI's
# Jinja2Templates.TemplateResponse() call path differs enough between
# those two that it crashed every request with `TypeError: unhashable
# type: 'dict'` deep inside Jinja2's template cache (confirmed live on
# PowerAI: every GET / 500'd immediately after deploy). Hand-picking which
# transitive packages "matter enough" to pin is exactly the kind of thing
# that's invisible until it silently isn't -- so now every line here comes
# from a real `pip freeze` of an install that was *constrained* (`pip
# install -c k9-aif-framework/requirements.txt -r <direct list>`) to the
# framework's already-proven versions, not hand-curated.
#
# Verified for real this time, not just import-checked: started
# `uvicorn k9chat.app:app` for real against this exact frozen environment
# and issued live HTTP requests (GET /, and the other lazy-import paths
# exercised directly) -- see the commit this file ships in for the exact
# commands. Re-verify the same way (constrain + freeze + live HTTP request,
# not just `python -c "import ..."`) for any future change to this file.
#
# pysqlite3-binary is absent from a `pip freeze` taken on macOS (its own
# `sys_platform == "linux"` marker correctly skips it there) -- kept here
# by hand since the actual deploy target (PowerAI, RHEL UBI9 base image)
# is Linux and chromadb_adapter.py's `import pysqlite3` shim needs it.
#
# When updating: change k9-aif-framework/requirements.txt first if a
# version needs to move, then re-run the constrain+freeze+verify process
# above against the new pin -- don't hand-edit a version number here.
